# Запуск wishlist-service в Kubernetes

Для запуска в одноузловом minikube подготовлены манифесты приложения, PostgreSQL и миграций. Backend и frontend находятся в одном образе: Go-сервер отдаёт HTML/CSS/JavaScript и REST API.

## Использованные абстракции

| Ресурс | Назначение |
|---|---|
| Namespace `wishlist` | Объединяет ресурсы проекта в одной области кластера. |
| ConfigMap `wishlist-config` | Хранит обычные настройки: HTTP-порт, путь к миграциям, режим Gin, имя БД и пользователя. |
| Secret `wishlist-secrets` | Передаёт пароль PostgreSQL, строку подключения и ключ JWT в контейнеры. В исходниках оставлен шаблон без настоящих секретов. |
| Deployment `wishlist-service` | Поддерживает нужное количество копий приложения и позволяет увеличивать число реплик. |
| StatefulSet `postgres` | Поддерживает одну копию PostgreSQL с постоянным именем Pod и отдельным хранилищем. |
| Service `wishlist-service` | Предоставляет доступ к приложению через NodePort 30080 и направляет соединения к готовым репликам. |
| Service `postgres` | Предоставляет внутреннее DNS-имя PostgreSQL. Используется headless Service. |
| Job `wishlist-migrate` | Однократно запускает миграции отдельной командой из образа приложения. |
| PersistentVolumeClaim | Запрашивает 1 ГиБ хранилища для PostgreSQL через StorageClass `standard`. Создаётся из шаблона StatefulSet. |
| Pod | Содержит контейнер приложения, PostgreSQL или мигратора. Pods создаются соответствующими контроллерами. |

Для Pods заданы запросы и ограничения ресурсов. Проверки готовности управляют допуском трафика, а приложение также имеет проверку работоспособности для перезапуска зависшего контейнера.

## Взаимодействие сервисов

Браузер обращается к адресу узла minikube на порту 30080. Service `wishlist-service` направляет соединение на HTTP-порт 8080 одной из готовых реплик приложения. Через этот адрес доступны интерфейс и REST API.

Приложение подключается к PostgreSQL по внутреннему имени `postgres` на порту 5432. Все реплики используют одну БД и общий ключ JWT, поэтому данные пользователя доступны независимо от выбранной реплики. PostgreSQL сохраняет данные в подключённом постоянном хранилище.

Job миграций подключается к той же БД. Порядок запуска: настройки и PostgreSQL, ожидание готовности БД, выполнение миграций, затем приложение. Миграции не входят в запуск HTTP-сервера.

При масштабировании увеличивается число реплик приложения; PostgreSQL остаётся в одной реплике. Команды сборки и запуска приведены в `README.md` этой папки.
