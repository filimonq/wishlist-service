# Экспорт и сбор метрик wishlist-service

## Приложение и стек

Wishlist-service позволяет регистрироваться, создавать списки желаний, добавлять подарки и бронировать их по публичной ссылке. Backend написан на Go с Gin и pgx, данные хранятся в PostgreSQL 18. Frontend — HTML, CSS и JavaScript, встроенные в Go-приложение.

Приложение и мониторинг развёрнуты в minikube. Для метрик используются:

| Компонент | Назначение |
|---|---|
| `prometheus/client_golang v1.23.2` | Метрики Go, процесса, HTTP и бизнес-операций |
| `postgres-exporter v0.20.0` | Экспорт статистики PostgreSQL |
| `vmagent v1.154.0` | Обнаружение подов, сбор и отправка метрик |
| `VictoriaMetrics v1.154.0` | Хранение временных рядов и выполнение запросов |

VictoriaMetrics установлена официальным Helm-чартом `victoria-metrics-single` версии `0.49.0`, vmagent — чартом `victoria-metrics-agent` версии `0.50.0`. Они работают в namespace `monitoring`, приложение и БД — в `wishlist`. Для VictoriaMetrics выделен PVC 2 GiB, срок хранения метрик — 7 дней.

## Как собираются метрики

```text
Go-приложение :9090/metrics ──┐
                             ├── vmagent ── VictoriaMetrics :8428
postgres-exporter :9187/metrics ┘
        │
        └── SQL → PostgreSQL :5432
```

Используется pull-модель: vmagent раз в 15 секунд запрашивает `/metrics`, затем отправляет значения в VictoriaMetrics через remote write. Приложение отдаёт метрики в формате Prometheus/OpenMetrics без авторизации на отдельном порту `9090`. Этот порт не опубликован через NodePort; публичный порт приложения обслуживает UI и REST API.

Service discovery настроен через Kubernetes API. На шаблонах подов приложения и PostgreSQL указаны аннотации `prometheus.io/scrape`, `prometheus.io/port` и `prometheus.io/path`. vmagent находит запущенные поды в `wishlist` и выбирает нужный порт контейнера. При добавлении реплик менять список адресов вручную не требуется.

Для обнаружения используются ServiceAccount, Role и RoleBinding. vmagent разрешено читать поды в `wishlist`; доступа к Secret и прав на изменение ресурсов у него нет. К метрикам добавляются лейблы `namespace`, `pod`, `container` и `app`.

## Метрики рантайма и PostgreSQL

Готовые коллекторы `NewGoCollector` и `NewProcessCollector` собирают метрики goroutines, памяти, GC и процесса. Дополнительно экспортируются число HTTP-запросов `wishlist_http_requests_total` и гистограмма задержки `wishlist_http_request_duration_seconds`. У HTTP-метрик есть метод, шаблон маршрута и статус ответа. Пользовательские ID, токены и полные URL в лейблы не попадают.

postgres-exporter работает вторым контейнером в Pod PostgreSQL. Он подключается к БД через `localhost:5432`, читает статистику SQL-запросами и отдаёт её на `9187/metrics`. Пользователь и имя БД берутся из ConfigMap, пароль — из Secret. Экспортируются показатели соединений, транзакций, блокировок и другие метрики PostgreSQL.

## Бизнес-метрики

Реализованы четыре счётчика типа Counter:

| Метрика | Что считает | Когда увеличивается |
|---|---|---|
| `wishlist_user_registrations_total` | Регистрации пользователей | После сохранения нового пользователя в БД |
| `wishlist_user_logins_total` | Успешные входы | После проверки пароля и создания JWT |
| `wishlist_wishlists_created_total` | Созданные вишлисты | После сохранения вишлиста в БД |
| `wishlist_items_reserved_total` | Бронирования подарков | После успешного бронирования в БД |

Неуспешные операции не увеличивают счётчики. Каждый экземпляр приложения считает события с момента своего запуска; после перезапуска значения обнуляются. Это число выполненных операций, а не текущее количество записей в БД. Для анализа за период используются `rate()` и `increase()`, с агрегацией по репликам при необходимости.

## Результаты проверки

В minikube проверена вся цепочка сбора:

- VictoriaMetrics и vmagent запущены, PVC VictoriaMetrics находится в состоянии `Bound`.
- На странице vmagent `/targets` приложение и postgres-exporter имеют статус `UP`, ошибок сбора нет.
- Запрос `pg_up{namespace="wishlist"}` вернул `1`: экспортер подключился к БД.
- Запрос `go_goroutines{app="wishlist-service"}` вернул `11`: метрики Go поступают в VictoriaMetrics.
- После действий в UI у проверяемого экземпляра получены значения: регистрации — `1`, входы — `2`, созданные вишлисты — `1`, бронирования — `1`.
- После масштабирования приложения с одной до трёх реплик vmagent автоматически обнаружил новые поды. На странице `/targets` появились четыре цели со статусом `UP`: три экземпляра приложения и postgres-exporter. Ошибок сбора — `0`.

Настройки Helm и права discovery находятся в [victoria-metrics-values.yaml](victoria-metrics-values.yaml), [vmagent-values.yaml](vmagent-values.yaml) и [vmagent-rbac.yaml](vmagent-rbac.yaml). Экспортер БД и аннотации подов описаны в [postgres.yaml](../postgres.yaml) и [app.yaml](../app.yaml). Команды запуска и проверки приведены в [README.md](README.md).
